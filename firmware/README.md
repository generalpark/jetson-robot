# ESP32 주행 제어 펌웨어

로봇의 구동부를 맡는 마이크로컨트롤러 쪽 코드다. 두 가지 형태로 만들었다.

| 디렉토리 | 입력 | 용도 |
|---|---|---|
| `motor_ctrl` | USB 시리얼 명령 | 단독 테스트, PWM 자가검증 |
| `motor_uros` | ROS 2 `/cmd_vel` | 실제 주행. micro-ROS 노드로 동작 |

제어부(핀 배치, PWM 설정, 안전장치)는 둘이 같다.

## 드라이버를 지키는 부분

BTS7960은 정·역을 `RPWM` / `LPWM` 두 핀으로 나눠 받는다. 한쪽에 듀티를 주는 동안
반대쪽은 반드시 0이어야 한다. 둘 다 0이 아니면 하이사이드와 로우사이드가 동시에
열려 드라이버가 단락된다.

```cpp
if (speed >= 0) { ledcWrite(ch_rev, 0); ledcWrite(ch_fwd, speed); }
else            { ledcWrite(ch_fwd, 0); ledcWrite(ch_rev, -speed); }
```

한쪽을 먼저 0으로 내린 뒤 반대쪽을 올린다. 순서가 바뀌면 전환하는 순간 양쪽이
짧게 같이 살아난다.

PWM은 20kHz로 둔다. 가청대역 위라 모터에서 나는 고주파 소음이 줄어든다.

## 명령이 끊기면 멈춘다

```cpp
if (!stopped && millis() - last_cmd_ms > CMD_TIMEOUT_MS) driveStop();
```

500ms 동안 명령이 없으면 스스로 정지한다. 상위 제어기가 죽거나 USB가 빠졌을 때
**마지막 속도로 계속 달리는 것이 가장 위험하다**고 봤다. 멈춰 있는 로봇은 늦어질 뿐이지만
제어를 잃은 채 움직이는 로봇은 사고가 된다.

## PWM이 실제로 나가는지 확인한 방법

보드에 사용자 LED가 없고 오실로스코프도 로직 애널라이저도 없었다.
그래서 **출력 핀을 입력 핀에 점퍼선으로 연결해, 보드가 자기 출력을 자기가 읽게** 했다.

```
GPIO25 (PWM 출력) ──점퍼선── GPIO34 (입력 전용)
```

PWM 한 주기(20kHz = 50µs)보다 훨씬 긴 시간 동안 20,000번 읽어 HIGH 비율을 센다.
샘플링이 PWM과 동기화돼 있지 않으므로, 표본이 충분하면 그 비율이 듀티에 수렴한다.

| duty | 측정 | 기대 | 오차 |
|---:|---:|---:|---:|
| 0 | 0.0000 | 0.0000 | 0 |
| 32 | 0.1308 | 0.1255 | +0.53%p |
| 64 | 0.2603 | 0.2510 | +0.93%p |
| 96 | 0.3875 | 0.3765 | +1.10%p |
| 128 | 0.5138 | 0.5020 | +1.19%p |
| 160 | 0.6399 | 0.6275 | +1.25%p |
| 192 | 0.7574 | 0.7529 | +0.44%p |
| 224 | 0.8780 | 0.8784 | −0.04%p |
| 255 | 1.0000 | 1.0000 | 0 |

9개 지점 모두 선형이고 최대 오차는 1.25%p다.

오차가 양끝에서 0이고 중간에서 커지는 것은 측정 방식 때문이다. duty 0과 255는
전환 자체가 없어 오차가 생길 수 없고, 중간 구간은 상승·하강 에지에서 읽힐 확률이
있어 HIGH 쪽으로 미세하게 치우친다. 출력의 오차가 아니라 샘플링의 한계다.

실행: 시리얼로 `V` 를 보내면 위 표를 출력한다.

## ROS 2 연동

`motor_uros` 는 `/cmd_vel`(`geometry_msgs/Twist`)을 구독해 차동 구동으로 바꾼다.

```
v_left  = v - w * L / 2
v_right = v + w * L / 2
```

`MAX_SPEED`는 JGA25-370(12V, 170RPM)과 65mm 바퀴 기준 이론값 0.578 m/s에서
0.55로 잡았다. 무부하 회전수라 실제로는 더 낮다. **조립 후 실측해서 고칠 값이다.**

Jetson에서 micro-ROS Agent를 띄우면 보드가 ROS 2 노드로 참여한다.

```bash
~/robot/uros_agent.sh /dev/ttyUSB0
ros2 topic pub -r 10 /cmd_vel geometry_msgs/msg/Twist '{linear: {x: 0.3}}'
```

## 빌드 메모

- micro-ROS 빌드는 **Windows에서 동작하지 않는다.** 빌드 스크립트가 POSIX 셸을
  전제로 해서 `. install/setup.sh` 에서 멈춘다. Jetson(Linux)에서 빌드했다
- PlatformIO를 venv에 설치하면 `~/.platformio/penv` 가 없어 micro-ROS 의존성
  빌드가 실패한다. 해당 경로로 심볼릭 링크를 걸어 해결했다
- 이 보드는 DTR/RTS 자동 리셋이 동작하지 않는다. 업로드할 때 **BOOT를 누른 채로**
  둬야 다운로드 모드로 들어간다
- 시리얼 포트를 그냥 열면 DTR/RTS가 올라가면서 보드가 리셋되거나 부트 모드가 바뀐다.
  둘 다 내린 상태로 연 뒤 RTS를 한 번만 토글해 의도적으로 리셋한다
- micro-ROS Agent가 포트를 잡고 있으면 업로드가 실패한다. 먼저 컨테이너를 내린다
